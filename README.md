# 隙见

隙见是一款基于真实评论证据的 AI 内容机会发现与选题决策工具。当前代码完成前四个阶段：评论数据闭环、机会发现、可追溯核心界面，以及完整 Brief 生成与稳定演示能力。

## 本地启动

要求 Python 3.10 或更高版本。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python app.py
```

打开终端显示的本地地址，默认通常为 `http://127.0.0.1:7860`。

## 第一阶段能力

- CSV、XLSX、每行一条的粘贴文本和内置示例四种入口；
- 自动识别 `comment`、`content`、`text`、`评论内容` 等评论列，无法识别时可手动选择；
- 预览、异常行统计、平台字段与点赞字段检测；
- HTML、不可见字符、全半角与重复标点清洗；
- 纯数字、纯表情和低信息评论标记；
- 完全重复去重、重复次数记录、稳定匿名评论 ID 与质量摘要；
- 全部重复时阻止进入后续分析，少样本与低有效率时提示风险。

## 第二阶段能力

- OpenAI 兼容大模型接口，支持环境变量、超时、失败重试和 JSON 解析；
- 30-60 条批处理、评论 ID 完整性校验、非法信号拦截及失败批次保留；
- 需求矛盾、高频疑问、观点分歧、对比需求和隐藏场景五类信号；
- 中文字符向量、余弦相似度和层次聚类生成内容机会；
- 评论数、覆盖率、隙值、优先级和可信度全部由程序计算；
- 未配置 API Key 时使用本地确定性分析，示例流程仍可完整运行。

## 第三阶段能力

- 六步分析进度、任务状态、失败批次重试、重新分析和完成后自动跳转；
- 示例案例预计算结果，可直接查看并保留完整重新分析入口；
- 内容机会总览、五类信号分布、隙值/评论数排序和信号/优先级筛选；
- 正式机会与低频弱信号分开展示，避免用不足证据填充机会卡片；
- 五维评分解释、关联评论证据链及强表达、高频疑问、不同观点和高赞筛选；
- 机会详情可携带当前机会 ID 进入内容 Brief。

## 第四阶段能力

- 每个正式机会生成三份差异化 Brief，完整覆盖目标人群、问题、角度、形式、钩子、结构、观点、依据和风险提示；
- 每份方案绑定当前机会内至少三条匿名真实评论，并拦截绝对化或无法验证的表达；
- 支持单方案重新生成、标题复制、完整 Brief 复制和 Markdown 报告导出；
- SQLite 保存任务、清洗评论、信号、机会、Brief 与最近任务快照，刷新后自动恢复；
- 内置无糖饮料示例预生成 18 份 Brief，AI 不可用时仍可完整演示；
- 导出文件自动清理，API Key 不进入页面、日志或版本库。

## 第五阶段能力

- CSV、XLSX、文本、异常输入、AI 超时/JSON 错误及关键词降级的发布测试；
- 连续主链路验收、证据追溯率和数字程序计算率自动复核；
- 固定生产依赖、Dockerfile 与 ModelScope `0.0.0.0:7860` 部署配置；
- 比赛测试报告、3 分钟讲解脚本、视频分镜、产品截图和提交检查材料；
- 100 行人工标注工作台和普通大模型对照实验协议，未完成真人部分会明确标记。

## 总体验收能力

- SQLite 产品埋点覆盖示例、任务、导入、分析、机会、证据、Brief、复制和导出；
- 埋点只保存任务/机会 ID 与安全元数据，拒绝评论正文、API Key 和令牌字段；
- `scripts/validate_release.py` 复核追溯率和程序计数，`scripts/analytics_report.py` 输出漏斗统计；
- 技术、安全、性能、边界与 MVP 总验收记录见 [06-技术与验收补充.md](06-技术与验收补充.md)。

## ModelScope 部署

项目根目录已提供 `Dockerfile`，默认监听 `0.0.0.0:7860`。创空间仅需安装 `requirements.txt`；`LLM_API_KEY` 等密钥通过平台环境变量配置，不配置时使用内置无糖饮料示例。

上传前运行 `python scripts/check_deploy_layout.py`，确认关键文件、业务包目录和 Python 模块命名均适合部署。

部署步骤、发布后检查和比赛材料位于 [materials/DEPLOYMENT.md](materials/DEPLOYMENT.md)。

真实 API Key 只能写入本地 `.env`，不要提交到仓库。可按 `.env.example` 配置兼容接口；未配置时自动使用本地分析。
